# 采用两阶段菜谱推荐

当用户请求“有啥吃啥”推荐时，默认返回三个按匹配度排序的候选菜，而不是直接展开完整菜谱。即使高匹配候选不足三个，也可以使用较弱匹配的菜谱补足，但必须明确标注其匹配程度，并说明主要差距。每个候选只展示菜名、简短特点、已有食材匹配情况、仍缺少的关键食材和预计难度；基础调料若已存在于常备品档案中，不重复列为缺失项。

用户选中候选后，再展示完整用料、步骤、预计用时、替代建议和需要注意的饮食约束。这样可以降低首轮信息量，让用户先决定想吃什么，同时保留推荐依据的可解释性。

推荐排序既考虑菜谱所需食材的满足程度，也奖励对用户锚点食材的利用。当用户只提供一种锚点食材时，不要求菜谱利用更多种现有食材，而应优先选择真正以该食材为主体的菜谱，并依次考虑关键食材缺口、是否可以立即制作以及三个候选之间的做法差异。常备调料可以参与匹配，但不得把未声明的新鲜配菜推定为已有。
